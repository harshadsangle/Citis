# CITIS LMS — Blueprint Gap Analysis and Missing-Only Implementation

We have an existing CITIS LMS implementation in this repository.

The following is the **approved target LMS workflow**. Use it as the reference specification for this task.

IMPORTANT:

* First inspect the existing repository thoroughly.
* Compare the current implementation against the workflow below.
* Do NOT reimplement functionality that already exists.
* Do NOT modify working functionality unnecessarily.
* Do NOT rewrite existing authentication, payment, certificate, RBAC, security, or deployment systems unless a genuine blueprint gap requires it.
* Preserve all existing data, APIs, routes, roles, permissions, tenant isolation, and working workflows.
* Do NOT create duplicate tables, APIs, pages, or components for functionality that already exists.
* Do NOT change database schema unless a genuinely missing blueprint feature requires it.
* Do NOT deploy or push anything automatically.
* Work only on genuine gaps after completing the audit.

# CRITICAL IMPLEMENTATION RULE

After completing the audit:

### ONLY implement genuine MISSING or required PARTIAL functionality.

Do NOT implement:

* already-working features
* duplicate workflows
* duplicate database tables
* duplicate APIs
* duplicate UI
* unnecessary refactors
* unrelated security improvements
* unrelated redesigns

For every proposed change explain:

1. Blueprint requirement
2. Existing implementation
3. Exact gap
4. Why the existing implementation does not satisfy the requirement
5. Files/database/API/UI that need modification
6. Whether migration is actually required

### Phase 4 — Assessment

Only if confirmed to be part of the current implementation scope:

* Live classes

* Admin Portal

# VERIFICATION REQUIREMENTS

After each implementation phase:

* Run relevant tests.
* Run API build/type check.
* Run affected portal build/type check.
* Run `git diff --check`.
* Verify existing authentication and RBAC behavior remains intact.
* Verify tenant isolation.
* Verify existing course/resource/enrollment workflows.
* Verify existing certificate approval workflow.
* Verify existing payment/refund workflow where affected.
* Do not deploy automatically.

At the end provide:

## FINAL GAP REPORT

### Implemented

Everything newly implemented.

### Already Existing

Everything reused without reimplementation.

### Remaining Missing

Only genuine remaining blueprint gaps.

### Differences

Existing functionality that intentionally differs from the blueprint.

### Unverified

Anything that requires production/live verification.

### Tests

Exact test/build results.

### Database Changes

Only migrations actually required and created.

### Deployment

Explicitly state that no deployment/push was performed unless requested.

Most importantly:

**Do not start by coding.**
First inspect and produce the gap analysis.
Then implement ONLY the confirmed missing functionality.
